# 推し色（顧客が選ぶアクセント）

## 目的

グッズやメンバーに合わせて、アプリの **アクセント色** を自分用にできること。  
大型ユニット（20人規模）でも足りるよう、**かなりの数を選べる**前提。

## カラータグとの違い（重要）

| | 推し色（この文書） | カラータグ |
|--|-------------------|------------|
| 用途 | アプリ全体の見た目（ボタン等） | 製品に付ける色ラベル |
| UI | 設定などでスウォッチ選択 | `/settings/color-tags` |
| 枠数 | 多数（プリセット＋任意色） | **現状のまま（変更しない）** |

**統合しない。** 用途が違う。

## 顧客向け UX（必須）

1. **色の丸（スウォッチ）をタップするだけ**で選べる  
2. 名前の長いテーマ一覧を主操作にしない  
3. プリセットを十分用意する（メンバー色・定番推し色を想定）  
4. 足りなければ **自分の色**（カラーピッカー / hex）も可  
5. 選んだ色はすぐ画面に反映され、「保存された」と分かる短いフィードバック

## 反映範囲

| 変えてよい | 変えない（原則） |
|------------|------------------|
| `--primary` / `--primary-foreground` | シェルの `--background` 全面 |
| `--ring`（フォーカス） | 本文の可読性を壊すコントラスト |
| 小さなアクセント・チャートの一部 | 危険色（destructive）の意味 |

背景ごと塗り替えて「テーマ丸ごと入替」にしない。可読性とブランド骨格を守る。

## ブランド既定との関係

未選択時や初回は、ブランドの種（`#9f606c`）由来の既定アクセントでよい。  
説明: [brand-palette.md](brand-palette.md)（スケール詳細は後回し）。

## 実装メモ（フェーズ1以降）

- 保存先は既存のテーマ同期（`user_metadata` / API）と整合させる  
- 現行 ThemePicker のセレクト UI は、スウォッチ UI に置き換える  
- プリセット一覧の具体色は Lab 後に `tokens` / コードへ  

## Do / Don't

| Do | Don't |
|----|-------|
| スウォッチ多数 + 任意色 | 推し色を3色だけに制限する提案 |
| アクセントのみ差し替え | 推し色＝シェル全面変更 |
| カラータグと説明を分ける | カラータグ枠を勝手に増減する |
