# デザイン変更時の3案比較（Design Lab）

見た目・トークン・主要レイアウトを変えるとき、**いきなり本番画面だけを1案で書き換えない。**  
手順の詳細・スコア表は skill **`design-lab`** が正（エージェント用）。ここは人向けの要約。

## 二層（この順）

1. **配置・部品・UI/UX**（3案の主差）  
2. **色の割り当て**（どのセマンティック役割／テーマ色を使うか。**全案でテーマ色あり**）

**A 用途最適 = 無彩色、ではない。** C と同系の色のまま、配置だけ用途最短にする。

## 3案の軸（固定）

| 案 | 名前 | ねらい |
|----|------|--------|
| A | 用途最適 | 仕事が早く終わる **配置**（色は C と同系＋テーマ色） |
| B | 推し活・遊び | 写真・テーマ色の実感・動きで楽しさ |
| C | ブランド整合 | 原則どおりの余白・階層・色の置き方 |

**AI推奨は4列目にしない。** スコア表で「推奨は〇」。

## 端末切替（Lab 上部）

| 表示 | 内容 |
|------|------|
| Web・PC | 3列比較。**拡大**で全画面＋幅可変（768px〜最大）の振る舞い確認 |
| Web・モバイル | スマホ幅のブラウザ枠。**向き: 縦 / 横 / 縦+横（同時）** |
| モバイルアプリ | Expo 想定（下タブ付きフレーム）。**向きは Web・モバイルと同じ** |

PC 拡大はスライダー・プリセット・右端ドラッグで幅変更。案 A/B/C も切替可。  
スマホ向きは Lab 上部の「向き:」で切替。縦+横は同じ案を2枠並べて見比べる。

### Lab 付帯（実装済）

- ログイン後シェル見本（本番ナビに近い）
- 状態: 通常 / 空 / 読込 / エラー / 成功
- 色プレビュー用スウォッチ（Lab 内の簡易プレビュー。**本番テーマはトークン一式** — [themes.md](themes.md)）
- 仮採用メモ（localStorage）
- コントラスト目安
- **色覚プレビュー**（1型／2型／3型／全色盲・近似。3列まとめて）
- **UX補助**: 親指ゾーン（モバイル）· 文字大きめ · 低輝度／屋外
- **スマホ向き**: 縦 / 横 / 縦+横（同時）。Web・モバイルとアプリで共通
- モバイル実機用 QR + URL コピー

### Lab 付帯（未実装・後回し）

- **セーフエリア（ノッチ）線** — Expo／アプリ本番に近くなってから（fb-001）。ノッチ・ホームバーに UI が埋まらないかのガイドライン

## いつ必須か

- レイアウト／余白／部品配置／モーション方針の変更  
- ブランド既定の印象を変える変更  

比較なしでよい例: 文言のみ、バグ復旧、テーマプリセットの1色追加。

## 手順（要約）

1. 何を比べるか1行で決める  
2. `/dev/design-lab` で案 A/B/C を実装並列  
3. 端末を切り替えて確認  
4. エージェントがスコア＋AI推奨  
5. **人が本決定**  
6. 選ばれた1案だけ本番へ  

## 比較の場

| 手段 | 状態 |
|------|------|
| `/dev/design-lab` | **実装済**（開発時のみ・**未ログイン可**。本番は 404。デザイン確認専用） |
| 設定ハブ | 開発時のみリンク |
| 本番 | Lab を出さない |

## 禁止

- A を無彩色・テーマ色なしにする  
- テーマ色を減らすことが比較の目的  
- 比較せず本番を一気に別トーンにすること  
- 「primary/ring だけ」を本番テーマの正にすること  
- ARCHIVE の Dash DESIGN を正にすること
