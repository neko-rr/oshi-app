# アクセシビリティ（a11y）

**目標レベル:** [WCAG 2.2](https://www.w3.org/TR/WCAG22/) **Level AA**（W3C Recommendation）。  
プロジェクト内の要約はここ。**仕様の正は常に公式**（記憶や古いメモだけで決めない）。

## 最新情報の取り方（必須）

推し色・コントラスト・フォーカス・モーション・タップ領域を変える前に skill **`design-a11y`** を実行せよ。

1. 索引: [docs/refs/official-links.md](../refs/official-links.md) の「アクセシビリティ・UX」  
2. **WebFetch** で現行ページを開く（最低1本）  
3. 要約と実装チェックをユーザーへ短く報告してからコード変更  

ローカルのこの文書だけを「最新仕様」扱いにするな。

## このアプリで必ず守る（要約）

| 項目 | 方針 | 関連 SC（目安） |
|------|------|----------------|
| コントラスト | 本文・主ボタンは十分な対比。推し色変更時は Lab のコントラストヒントも見る | 1.4.3 Contrast (Minimum) |
| フォーカス | shadcn の focus-visible を消さない。モーダルでフォーカスを隠さない | 2.4.7 / 2.4.11 Focus Not Obscured |
| タップ領域 | 主操作は十分な大きさ（目安 24×24 CSS px 以上） | 2.5.8 Target Size |
| アイコンのみ | `aria-label`（または可視ラベル）必須 | 4.1.2 Name, Role, Value |
| 動き | `prefers-reduced-motion` で装飾モーションを切る | 2.3.3 Animation from Interactions |
| 色だけに依存しない | エラーは色＋テキスト。Lab の色覚プレビューで確認 | 1.4.1 Use of Color |

## Do / Don't

| Do | Don't |
|----|-------|
| `@/components/ui` の Button / Input | フォーカスリングを `outline-none` だけで消す |
| 推し色はアクセント。本文は十分な対比 | 薄い推し色テキストを小さな字で置く |
| Lab コントラストヒント＋**色覚プレビュー**を参考にする | コントラスト未確認で本番全面採用 |
| エラー文言をフィールド近くに出す | 赤枠だけでエラーを伝える |

## Design Lab の色覚プレビュー

`/dev/design-lab` ヘッダーの「色覚」で、1型／2型／3型／全色盲の **近似シミュレーション**（SVG `feColorMatrix`）。  
3案まとめて適用。**臨床診断ではない。** Chrome DevTools と同系統の考え方。

## Design Lab の UX 補助（専門家でなくても見る）

| 補助 | 見ること |
|------|----------|
| 親指ゾーン | モバイル表示で主CTAが緑帯（下）にあるか |
| 文字大きめ | はみ出し・折り返しで読めなくなる箇所 |
| 低輝度／屋外 | コントラストの体感（数値ヒントと併用） |

いずれも **近似**。本番の絶対正解ではないが、採用前のチェックに使う。

## 推し色との関係

- 顧客が選ぶ推し色は **多様**。すべての組み合わせで AA を保証できない場合がある  
- 最低限: **デフォルト種＋主要スウォッチ**で Lab / 本番の主 CTA・ナビを確認  
- 不合格スウォッチは一覧から外すか、コントラスト確保用の上書きトークンを検討（勝手に推し色数を削らない）
