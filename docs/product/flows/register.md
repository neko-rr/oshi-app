# フロー: 製品登録（理想）

利用者画面の主経路は **手順 1 → 2 → 6**（3〜5 は裏側のアシスト。6 ではローディング表示可）。

製品はグッズ・漫画・書籍など多様。v2 では Web=`apps/web`、業務=`apps/api` services、照合は `/assist/*`。

## 現状との差

現行 UI は `RegisterWizard`（手順 1 → 2 → 6）で番号入力・カメラ読取・写真・確認まで完走できる（**Must 本線は shipped**）。  
**開始手順の既定:** `/settings/register` の `register_start_step`（`barcode` / `photo` / `confirm`）。「続けて登録」も同じ設定に従う。スキップ操作後に「次からこの手順」提案あり。  
**収納:** `default_storage_location_id` があれば確認画面で選択済み＋先頭。なければ登録時の選択履歴で並びのみ（自動選択なし）。  
**バーコード:** ライブカメラ（`BarcodeDetector` 優先、ZXing フォールバック）＋画像アップロード＋番号入力。映像は全幅寄り・横向きでも CTA が被らない配置。  
読取後は duplicate-hints（バーコード **または** 楽天 `external_item_code`）で自分の同グッズ件数・合計所持数をヒント表示（追加登録は妨げない）。  
**写真:** 選択直後に object URL プレビュー＋撮り直し。確認画面にもサムネ表示。  
**続けて登録:** 成功後の主CTA。イベント束（作品シリーズ名・キャラ・購入日）＋収納・カテゴリ・カラータグ枠・通貨を引き継ぎ。製品名・グループ・タイトル／バーコード／写真／メモ／価格／購入場所／数量フラグ／外部URLはクリア。開始手順は `/settings/register` に従う。確認画面の「全部消す」でイベント束・タグ束をワンタップ解除できる。  
**裏アシスト:** 写真あり時は `POST /assist/vision/describe` を **1回**呼び、見た目タグ・商品種類・色提案を確認画面へ反映。  
フィールド優先は **手入力 > バーコード照合値 > Vision**（商品名・価格・楽天外部参照はバーコード優先）。  
`/assist/tags/extract` は登録本線では呼ばない（API は残置）。  
**楽天照合:** 2026 新API。成功時は先頭候補を自動プレフィルし、確認画面で候補（最大5件）から差し替え可。確認画面ではキーワード検索も可。`genre_id` は Genre Search で名前取得しカテゴリ提案（soft）。選んだ候補の外部参照は `product_external_ref` へ。項目の正本は [register_fields.md](../register_fields.md)。  
**ダブり土台:** 所持数・交換OK（個数）・欲しいフラグ。設定の手元数＋余剰の自動交換OK。CLIP・交換専用画面は後続。  
**後続（Must 本線外）:** 店頭専用の購入済み判定画面、一括登録 / CLIP。

## 手順 1 — バーコード

- 同一画面の上から: **読取 → アップロード → 番号入力**
- カメラは可能ならライブプレビュー
- **スキップ** / **すべて手動入力** を用意
- 成功後は手順 2 へ（自動遷移または確定ボタン）
- 失敗時: 「もう一度」または「スキップ」
- Output: バーコード情報を照合 API へ（この段階の撮影バーコード画像は製品写真として保存しない）

担当の目安: Web 登録 UI + API `assist/barcode/*` +（将来）読取ヘルパー

## 手順 2 — 正面写真

- アップロードまたは撮影（ライブプレビュー可）
- **スキップ** / 「もう一度」可
- 初回登録は **正面写真のみ**（アップ気味を促す）
- 保存した写真は一覧サムネ・後の装飾に使う
- 確定後は手順 6 へ（3〜5 は裏で進行可）

担当の目安: `photo_service` / `POST /photos`（一覧からの追加写真でも再利用）

## 手順 3 — バーコード照合（裏）

- Input: 手順 1 のバーコード
- Output: 候補一覧（name / price / product_url / shop_name / external_item_code / image_url 等）
- 失敗しても利用者通知は不要 → 手順 4 へ
- 成功しても手順 4 へ（確認画面で先頭自動入力＋候補差し替え）

API: `POST /assist/barcode/lookup`（LIVE フラグ・キー方針は `docs/migration/v2/assist_external_apis.md`）

## 手順 4〜5 — 画像 Vision（裏・1回）

- Input: 手順 2 の写真（なければスキップ）
- IO Intelligence Vision を **1回**呼び、説明・`product_type`・色・見た目タグ（12〜16目安）を同時取得
- 種類は既存 `category_tag` 名とマッチして自動選択。色は `color_tag` 枠へ。見た目タグはチップ（メモ追記可）
- キー未設定 / LIVE オフでも soft status で落ちない
- 別呼び出しのタグ専用 LLM（`/assist/tags/extract`）は登録本線では使わない

API: `POST /assist/vision/describe`

## 手順 6 — 微調整と本登録

- Vision 待ち中はローディング表示可。**終わっていなくても登録ボタンで本保存可能**
- **常時表示:** 照合（候補・キーワード・楽天情報）・製品名（必須）・カテゴリ／収納／カラータグ
- **詳しく（既定クローズ）:** 作品シリーズ・タイトル・グループ・キャラ、所持数・交換OK・欲しい、購入価格／場所／購入日、バーコード・任意URL・メモ・見た目タグ
- 「全部消す」でイベント束（作品・キャラ・購入日・収納）とタグ束（カテゴリ・色）をクリア。通貨は設定既定へ
- 登録成功後は「続けて登録」（設定の開始手順へ）またはギャラリーへ。成功後も「全部消す」可

本保存: `POST /photos`（任意）+ `POST /products`（`external_refs` 任意。アシスト成功は必須にしない）

## やらないこと（このフロー内）

- 登録の本保存を外部アシスト成功に必須化しない
- 写真を学習用データセットとして外部に残す実装をしない
- Dash 期の `EDA.py` や curl 例を正本にしない（探索は別・一時）
