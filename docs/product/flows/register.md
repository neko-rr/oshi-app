# フロー: 製品登録（理想）

利用者画面の主経路は **手順 1 → 2 → 6**（3〜5 は裏側のアシスト。6 ではローディング表示可）。

製品はグッズ・漫画・書籍など多様。v2 では Web=`apps/web`、業務=`apps/api` services、照合は `/assist/*`。

## 現状との差

現行 UI は `RegisterWizard`（手順 1 → 2 → 6）で番号入力・カメラ読取・写真・確認まで完走できる。  
**バーコード:** ライブカメラ（`BarcodeDetector` 優先、ZXing フォールバック）＋画像アップロード＋番号入力。  
読取後は `GET /products?barcode=` で自分のリストに同番号があるかヒント表示（将来の購入済み判定の土台）。  
**未実装:** Vision / タグ抽出の LIVE オーケストレーション、店頭専用の購入済み判定画面。  
楽天 LIVE は仕様変更により当面オフ前提。

## 手順 1 — バーコード

- 同一画面の上から: **読取 → アップロード → 番号入力**
- カメラは可能ならライブプレビュー
- **スキップ** / **すべて手動入力** を用意
- 成功後は手順 2 へ（自動遷移または確定ボタン）
- 失敗時: 「もう一度」または「スキップ」
- Output: バーコード情報を照合 API へ（この段階の撮影バーコード画像は製品写真として保存しない）

担当の目安: Web 登録 UI + API `assist/barcode/*` +（将来）読取ヘルパー

## 手順 2 — 正面写真

- アップロードまたは撮影（ライブプレビュー可）
- **スキップ** / 「もう一度」可
- 初回登録は **正面写真のみ**（アップ気味を促す）
- 保存した写真は一覧サムネ・後の装飾に使う
- 確定後は手順 6 へ（3〜5 は裏で進行可）

担当の目安: `photo_service` / `POST /photos`（一覧からの追加写真でも再利用）

## 手順 3 — バーコード照合（裏）

- Input: 手順 1 のバーコード
- Output: 製品情報（登録・タグ用）
- 失敗しても利用者通知は不要 → 手順 4 へ
- 成功しても手順 4 へ

API: `POST /assist/barcode/lookup`（LIVE フラグ・キー方針は `docs/migration/v2/assist_external_apis.md`）

## 手順 4 — 画像説明（裏）

- Input: 手順 2 の写真
- IO Intelligence Vision を使う（キー未設定時は接続しない）
- 手順 3 失敗時は、画像テキスト化結果などでキーワード照合を検討
- 手順 3 成功時は説明テキスト化が主

API: `POST /assist/vision/describe`、必要なら `assist/barcode/keyword`

## 手順 5 — タグ抽出（裏）

- 手順 3・4 の情報から登録用タグを抽出
- 1 と 2 を両方スキップした場合は提案なし → 手順 6 で手入力

API: `POST /assist/tags/extract`

## 手順 6 — 微調整と本登録

- 3〜5 の完了待ち中はローディングを表示してよい
- **タグ抽出が終わっていなくても登録ボタンで本保存可能**
- 提案を表示し、利用者が修正
- 登録成功の通知のあと、手順 1 に戻る

本保存: `POST /photos`（任意）+ `POST /products`（アシストに依存しない）

## やらないこと（このフロー内）

- 登録の本保存を外部アシスト成功に必須化しない
- 写真を学習用データセットとして外部に残す実装をしない
- Dash 期の `EDA.py` や curl 例を正本にしない（探索は別・一時）
