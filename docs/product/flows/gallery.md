# フロー: ギャラリー（一覧・詳細）

登録済みグッズを **写真主役** で眺め、タグやキーワードで探し、詳細または編集モードで直して戻る。  
対象は Web（`/gallery`）。Mobile は後続。

## 一覧 `/gallery`

1. ログイン必須。自分の製品だけ（RLS + API）。
2. グリッド／大きめ／リストは見た目設定の `gallery_layout`（設定画面）。写真フィットは `gallery_image_fit`（cover／contain。「はみ出し少なめ」）。**大きめレイアウトは常に contain**。
3. **検索 `q`**: 製品名・カテゴリ名・収納名の部分一致。**ページを跨いで正確**（DB 側フィルタ後に limit/offset）。
4. **最近使った条件**: 検索語・タグ・グッズの色・交換OK・欲しい・価格なし・購入日なし・購入月・カテゴリなし・収納なし・写真なし・同じバーコードを端末に最大8件。ギャラリーからチップで再適用（保存ビューとは別）。
5. **チップ絞り込み**（複数可）:
   - カテゴリ / 収納 / カラータグ（スロット） / グッズの色（固定15色。名前で探せる。同種 OR）
   - 交換OK / 欲しい / 価格なし / 購入日なし / カテゴリなし / 収納なし / 写真なし / 同じバーコード（それぞれオンの製品だけ。複数選ぶと AND。URL は `sales_desired=1` / `want_object=1` / `missing_price=1` / `missing_purchase_date=1` / `missing_category=1` / `missing_storage=1` / `missing_photo=1` / `duplicate_barcode=1`。省略は絞らない）
   - 同じバーコードは、前後の空白を除いた番号が2件以上ある品だけ。空の番号は含めない。楽天の商品コードでは絞らない
   - 購入月（`purchase_month=YYYY-MM`。統計の月から来る。チップは付いているときだけ出て、押すと外れる）
   - **同種は OR、異種は AND**
   - URL: `category_tag_id=1,2` / `storage_location_id=…` / `color_tag_slot=1,3` / `product_color=pink,black`（単一 ID も互換）
   - **クエリ版** `v=1`: 同種 OR・異種 AND の契約。パラメータがあるときだけ付与（API には送らない）。当面版上げしない
   - **いまの条件**: 上部に件数要約（例: カテゴリ2・収納1・色1。検索語ありなら「検索」も）＋一発クリア（並びは残す）
6. **並び**: 一覧上で newest / name / created_at。URL `sort` に載せ、同時に `display_settings.list_sort` も更新。
7. **保存ビュー**（無料・上限20）: いまの条件（検索・タグ・グッズの色・交換OK・欲しい・価格なし・購入日なし・購入月・カテゴリなし・収納なし・写真なし・同じバーコード・並び）に名前を付けて保存。タップで `v=1` クエリへ適用。削除可。表 `gallery_view`（JSON 黒箱なし。フラグは boolean 列。購入月は text。グッズの色は `product_color_codes`）。
8. **もっと見る**: `has_more` が true のとき次ページ（同フィルタで offset 加算）。
9. **一括更新**: 「選択」→ 範囲操作（このページ全選択／条件結果を最大100件選択／選択した N 件だけ表示）→ カードを選ぶ → **収納**または**カテゴリ**を変更（`PATCH /products/bulk`）。クリア（なし）も可。
10. **編集モード**: 「編集」で写真つきリストになる（グリッド／大きめは使わない）。「選択」とは同時に入らない。読み込み済みの各行で登録項目を直し、変えた行だけ `PATCH /products/{id}` で保存する。画面の「基本 / 詳しく」で全行の見える項目を揃える。基本は製品名・カテゴリ・収納・グッズの色・カラータグ。詳しくはグループ・作品シリーズ・タイトル・キャラ・所持数・交換OK・欲しい・価格・通貨・購入場所・購入日・バーコード・メモ・楽天URL・任意URL。写真は左右 90 度だけ（画素を回して保存。別写真への差し替えはしない。写真が無い行は回転しない）。未保存で抜けるときは確認。失敗した行は残し、成功した行は確定に戻す。
11. カードタップ → 詳細（選択モード中は選択切替。編集モード中は行の入力）。リンクに現在の一覧クエリを引き継ぐ。一覧の並びは詳細の隣遷移用に保持。
12. 空状態: 未登録なら登録へ CTA。絞込ゼロ件なら条件クリアの案内。
13. 登録直後 `?registered=` で軽い成功メッセージ可。

URL 状態の例: `/gallery?v=1&category_tag_id=1,2&storage_location_id=3&color_tag_slot=1&sort=name`

## 詳細 `/gallery/[registered_product_id]`

1. 自分の製品のみ。他人は 404（存在漏洩しない方針）。
2. 写真（高解像度優先）→ メタ → 編集。編集機能は落とさない。写真の撮り直しは詳細だけ（1件）。ファイル選択とカメラ撮影は別ボタン。選んでプレビューし、保存時に `POST /photos` して `PATCH` の `photo_id` を差し替える。自分の写真だけ。古い写真は他製品が参照していなければ消す。
3. 「← ギャラリー」は **一覧にいたときのクエリを復元** する（絞込・並び・offset）。
4. 一覧から開いたときは **前後ボタン／横スワイプ／矢印キー** で隣の製品へ（ライトボックス表示中はスワイプしない）。ディープリンクのみのときは非表示。

## 検索との関係

ギャラリー内の `q` が一覧検索の DoD。独立 `/search` は置かない。最近使った条件はギャラリー上で完結。

## やらない（このフロー）

- ギャラリー画面内のレイアウト／カード項目クイック切替（設定が本線）
- Mobile 専用画面
- 閲覧グリッド上でのその場編集（編集モードのリストに限る）
- 編集モードでの別写真への差し替え（回転のみ。撮り直しは詳細の1件）、定価、非表示の旧項目
- 100件超の一括（上限は API と UI で揃え、超分は絞り込み／分割で対応）
- 隣製品用の専用 API（クライアントの並び保持で足りる）
