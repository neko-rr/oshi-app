# Web 多言語（i18n）

## 方針

| 項目 | 内容 |
|------|------|
| ライブラリ | `next-intl` |
| ルーティング | `app/[locale]/...` + `localePrefix: 'as-needed'` |
| 既定 | **日本語** → `/gallery`（プレフィックスなし） |
| 英語 | `/en/gallery` |
| 記憶 | Cookie（`NEXT_LOCALE`）＋ URL が正 |
| 切替 UI | `/settings/theme`（見た目）の「表示言語」 |

## 言語を増やすとき

1. `apps/web/src/i18n/routing.ts` の `locales` に追加（例: `'fr'`）
2. `apps/web/messages/fr.json` を追加（`ja.json` を雛形）
3. `apps/web/src/lib/auth-path-policy.ts` の `APP_LOCALES` を揃える
4. middleware の matcher `(ja|en)` に新ロケールを足す
5. 設定の `LocaleSwitcher` にボタンを足す

ルートや画面コンポーネントの作り直しは不要（辞書と locales が主）。

## 文言（キー化の境界）

- 正本は **日本語**（`messages/ja.json`）。英語は同キーを `en.json` に置く
- **主要ユーザー画面は辞書経由済み**（設定・ギャラリー・検索・登録・ダッシュボード・Auth フォーム・Me・Privacy・Licenses・ナビ／フッター）
- 表示ラベル定数（`displayPrefs` / テーマ名 / タグプリセット名）も UI は辞書側。ID 自体は英語のまま
- **対象外**: Design Lab（`/dev/design-lab`）、開発者向けコメント、API／DB／メール文面、ルート layout の固定 metadata 一部
- `ja.json` と `en.json` のキー集合は一致させる

## 仕組み化（検知＋下書き）

| 何 | どこ |
|----|------|
| キー一致検査 | `python scripts/check_i18n_message_keys.py`（CI `web` job / `post-change-verify`） |
| ja→en 下書き | skill **`i18n-web-sync`** |
| 推し活・製品語 | [i18n_glossary.md](i18n_glossary.md) |

**やらないこと:** CI／hook での `en.json` 自動生成・上書き。検査は欠落検知のみ。

## UI 言語と日時・居住地

- **表示言語**（ja/en）は UI 文言と URL
- **居住地**は登録日などの日時表示と、購入価格の**表示用**通貨記号・桁区切り（`display_settings`）。既定は日本
- **製品ごとの法定通貨記録**は別機能（`product_currency_fiat` planned）。NFT／暗号は `crypto_nft_assets` deferred
- 両者は独立。見た目設定（`/settings/theme`）で別セクション

## Auth との関係

- middleware は論理パス（locale 除去後）で認証ゲートする
- 未ログイン Redirect は現在の locale プレフィックスを維持（例: `/en/gallery` → `/en/auth/login`）
