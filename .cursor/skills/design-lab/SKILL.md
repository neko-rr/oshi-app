# Design Lab（3案並列・スコア）

## いつ使うか（必須）

- 見た目・レイアウト・モーション方針を **本決定する前**
- 「どちらがよいか」を人が目で見て決める必要があるとき
- `docs/design/compare-workflow.md` が比較必須としている変更

単色追加・文言のみ・バグ復旧だけなら不要（`design-change` に従う）。

## デザインの二層（必ずこの順）

| 順 | 層 | 内容 |
|----|-----|------|
| 1 | **配置・部品・UI/UX** | 情報階層、主CTA、一覧の形、余白、動き。3案の主差はここ |
| 2 | **色の割り当て** | セマンティック役割／テーマ色。全案でテーマ色あり（本番はトークン一式 — `themes.md`） |

**A 用途最適 ≠ 無彩色。** A は C と同系の色使いのまま、**配置だけ用途最短**にする。

## 結論の形（守る）

| 項目 | 内容 |
|------|------|
| 並列の数 | **実装された姿を3案**（4列にしない） |
| 第4の「AI推奨」 | **列にしない**。スコア表＋推奨1つ |
| 端末切替 | Lab で **Web・PC / Web・モバイル / モバイルアプリ** を簡単切替。スマホ枠は **縦 / 横 / 縦+横（同時）** |
| 本決定 | 人が Lab を見て選ぶまで本番全体へ採用しない |

## 3案の固定軸

| 案ID | 名前 | ねらい（差は主に配置・部品） |
|------|------|------------------------------|
| A | **用途最適** | タスク最短の配置。色は C と同系＋テーマ色 |
| B | **推し活・遊び** | 写真・テーマ色の実感・動きで楽しさ（業務は壊さない） |
| C | **ブランド整合** | 原則どおりの余白・階層・色の置き方 |

色だけ変えた3コピー、または A からテーマ色を消した案は **不合格**。

## Lab 付帯機能（実装済）

| 機能 | 内容 |
|------|------|
| ログイン後シェル | 本番ナビに近い見本ヘッダー |
| UI 状態切替 | 通常 / 空 / 読込 / エラー / 成功（全案共通） |
| 色プレビュー | Lab 内スウォッチ（簡易）。**本番テーマは `colors.css` のトークン一式** |
| 仮採用メモ | localStorage（本決定はチャット） |
| コントラスト目安 | テーマ色×文字の AA 目安 |

| UX補助 | 親指ゾーン（モバイル）· 文字大きめ · 低輝度／屋外（近似） |

## 端末プレビュー（必須）

Lab（`/dev/design-lab`）上部で切り替え。**開発時は未ログインで閲覧可**（デザイン確認専用の見本。本番は出さない）。

| ID | 表示 |
|----|------|
| `web-pc` | 広いブラウザ。**拡大プレビュー**で全画面＋幅可変（768〜最大） |
| `web-mobile` | スマホ幅ブラウザ枠。**向き: 縦 / 横 / 縦+横** |
| `mobile-app` | Expo 想定（ステータスバー＋下タブ）。**向き: 縦 / 横 / 縦+横** |

スマホ向きは Lab 上部「向き:」で切替。`縦+横` は同じ案を2枠並べて同時確認。

Web・PC の拡大は必須機能。幅変更で折り返し・列数の変化を人が確認できるようにする。

スコア提示時は、どの端末で見たか（または「3端末とも確認」）を1行書く。  
モバイルでは親指圏・下タブとの干渉も UI/UX チェックに含める。

## UI/UX 必須チェック（各案）

1. **主目的** — 達成すること  
2. **次の一手** — 主アクション  
3. **視線・親指** — PC / スマホで適切か  
4. **状態** — 空・読込・エラー・成功  
5. **動き** — `motion.md` の範囲か  
6. **テーマ色** — **全案にあるか**。本番はセマンティック変数一式（hex 直書きなし。`themes.md`）  
7. **色の役割** — primary / muted / destructive 等の割り当てが説明できるか  
8. **色覚** — Lab の色覚プレビューで、色だけに頼った区別になっていないか  
9. **届く・読める・見える** — 親指ゾーン／文字サイズ／低輝度・屋外で主CTAと本文を確認  

## スコア表

各観点 **1〜5**。加重平均 = Σ(点×重み) / Σ重み。

| 観点 | 重み | 説明 |
|------|------|------|
| 用途フィット | 3 | タスク完了・誤操作の少なさ（**配置**中心） |
| 認知のやさしさ | 2 | 次の行動が分かるか |
| 推し活・感情 | 2 | 写真・テーマ色の活き方（色を消して稼がない） |
| ブランド整合 | 2 | 原則・色の置き方・動き |
| 端末適合 | 2 | Web PC / Web モバイル / アプリ想定での使いやすさ |
| アクセシビリティ | 1 | コントラスト・タッチ・reduced-motion |
| 実装一貫性 | 1 | shadcn / トークン / hex直書きなし |

※「端末適合」を足したため、旧「アクセシビリティ」重みは 1。合計重み 13。

提示テンプレ:

```markdown

比較対象: （1行）

確認端末: Web・PC / Web・モバイル / モバイルアプリ（該当を書く）

| 観点（重み） | A 用途最適 | B 推し活・遊び | C ブランド整合 |
|--------------|------------|----------------|----------------|
| 用途フィット (3) | n | n | n |
| 認知のやさしさ (2) | n | n | n |
| 推し活・感情 (2) | n | n | n |
| ブランド整合 (2) | n | n | n |
| 端末適合 (2) | n | n | n |
| アクセシビリティ (1) | n | n | n |
| 実装一貫性 (1) | n | n | n |
| **加重平均** | x.x | x.x | x.x |

### AI推奨: 案〇（加重平均 x.x）
（配置の理由・色の割り当て・弱みを3〜5行）

```

同点なら用途フィット → ブランド整合の順。

## 実行手順

1. skill **`design-feedback`** で pending を確認（Lab 対象に関連があれば案に反映。未決は本番に入れない）  
2. `principles` / `motion` / `themes` / `oshi-accents` を確認  
3. 比較対象を1行で固定  
4. `/dev/design-lab` に3案を実装（色だけで差を付けない。A にテーマ色を残す）  
5. 端末切替が使えること  
6. スコア＋AI推奨を提示  
7. **人の本決定を待つ**（未決なら `feedback_items.json` に pending 記録可）  
8. 採用後は **`design-adoption`** で画面単位に本番反映（一括禁止）  

## 禁止

- A を「テーマ色なし／無彩色ツール風」にする  
- 4列目に AI推奨 UI  
- テーマ色を減らすことが比較の目的  
- Lab なしで本番一括採用  
- 「primary/ring だけ」を本番テーマの正にする  
- カラータグ仕様を Lab で変える  
- ARCHIVE の Dash DESIGN を正にする
